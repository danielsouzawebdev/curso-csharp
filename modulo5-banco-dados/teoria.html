1. Por que usar um banco de dados

Variáveis e listas vivem na memória e somem quando o programa fecha. Arquivos de texto resolvem casos simples, mas ficam difíceis quando há muitos dados, vários usuários, buscas rápidas e regras de integridade. Um SGBD (Sistema Gerenciador de Banco de Dados) oferece:

  • Persistência: os dados continuam salvos.
  • Consulta eficiente com a linguagem SQL.
  • Integridade: regras que impedem dados inconsistentes.
  • Concorrência: vários usuários ao mesmo tempo.
  • Segurança: controle de quem pode fazer o quê.

5. O Laragon

O Laragon é um ambiente de desenvolvimento para Windows que instala e inicia, com um clique, servidores como o MySQL/MariaDB. Ele também traz o HeidiSQL, programa gráfico para criar bancos, tabelas e testar SQL. Valores padrão comuns (confira na sua instalação): servidor localhost (ou 127.0.0.1), porta 3306, usuário root, senha vazia.

💡 Esses padrões servem para estudo em máquina local. Em sistemas reais nunca se usa root sem senha; veremos como criar um usuário com permissões limitadas.

6. Como o C# conversa com o banco (ADO.NET)

O C# usa um driver (aqui, o pacote MySqlConnector) com quatro peças principais:

ClasseFunção

Método do comandoQuando usar
ExecuteNonQuery()INSERT, UPDATE, DELETE (devolve quantas linhas foram afetadas)
ExecuteScalar()Consulta que devolve um único valor (ex.: COUNT(*))

Connection string: texto que diz onde está o banco e como entrar: Server=localhost;Port=3306;Database=estoque;User ID=root;Password=;

🔐 Configuração didáticaO usuário root com senha vazia é usado aqui apenas para simplificar um servidor local de laboratório. Em um sistema real, crie um usuário específico, use senha forte, conceda somente as permissões necessárias e não mantenha credenciais diretamente no código-fonte.

Regra de ouro: abrir a conexão o mais tarde possível e fechá-la o mais cedo possível. O bloco using fecha automaticamente, mesmo se ocorrer erro.

7. Segurança: SQL Injection

Ocorre quando o texto digitado pelo usuário é colado dentro do SQL, permitindo que ele altere o comando. É uma das falhas mais comuns e graves em sistemas.

// ❌ NUNCA FAÇA ISTO: concatenar o que o usuário digitou dentro do SQL
string sql = "SELECT * FROM usuarios WHERE login = '" + txtLogin.Text
           + "' AND senha = '" + txtSenha.Text + "'";

// Se o usuário digitar:  ' OR '1'='1   nos dois campos, o SQL vira:
// SELECT * FROM usuarios WHERE login = '' OR '1'='1' AND senha = '' OR '1'='1'
// A condição '1'='1' é sempre verdadeira: o sistema liberaria o acesso sem senha.
// ✅ FAÇA ASSIM: use parâmetros (@nome). O valor viaja separado do comando SQL.
var cmd = new MySqlCommand(
    "SELECT COUNT(*) FROM usuarios WHERE login = @login AND senha = @senha", con); // @login e @senha são "buracos"
cmd.Parameters.AddWithValue("@login", txtLogin.Text);  // o texto é tratado SEMPRE como dado, nunca como comando
cmd.Parameters.AddWithValue("@senha", txtSenha.Text);  // mesmo que contenha aspas ou SQL, não altera a consulta

Outras boas práticas: usar um usuário do banco com permissões mínimas; não guardar senhas de usuários em texto puro (usar hash); não deixar a senha do banco fixa no código em sistemas reais (usar arquivo de configuração ou variável de ambiente).
