Teoria

🧭 Objetivo desta etapaEntender como organizar estado e comportamento em objetos sem criar classes apenas por hábito.
Estratégia: leia uma seção por vez, execute mentalmente os exemplos e anote uma dúvida ou exemplo próprio antes de avançar para a prática.

1. Do estruturado ao orientado a objetos

Na programação estruturada, dados (variáveis) e funções ficam separados. Conforme o sistema cresce, fica difícil saber quais funções mexem em quais dados. Na POO, juntamos os dois: um objeto guarda seus dados (estado) e as funções que agem sobre eles (comportamento).

EstruturadoOrientado a objetos
Funções e variáveis soltasClasses que reúnem dados e comportamento
Dados acessíveis a todo o programaDados protegidos dentro do objeto
Reuso por cópia de código ou funçõesReuso por herança, composição e interfaces
Funciona bem para programas pequenosEscala melhor para sistemas grandes

Um objeto tem três características: identidade (é único), estado (valores dos dados) e comportamento (o que ele sabe fazer). Dois produtos podem ter o mesmo nome e preço e ainda serem objetos diferentes.

2. Classe e objeto

  • Classe: o molde (a planta da casa). Define quais dados e ações os objetos terão.
  • Objeto (instância): o que é criado a partir da classe (a casa construída). Criamos com new.
public class Pessoa                       // classe: o molde
{
    public string Nome { get; set; } = "";
    public int Idade { get; set; }
    public void Apresentar() => Console.WriteLine($"Oi, sou {Nome}.");
}

Pessoa ana = new Pessoa();                // objeto: criado com new
ana.Nome = "Ana";                         // acessa a propriedade com o ponto
ana.Apresentar();                         // chama o método

Referência e valor

Classes são tipos por referência: a variável guarda o endereço do objeto, e não o objeto em si. Por isso, Pessoa p2 = p1; não copia a pessoa: as duas variáveis apontam para o mesmo objeto. Já int, double, bool e struct são tipos por valor (a cópia é independente). Uma referência pode valer null (“não aponta para nenhum objeto”), e usar um membro de uma referência nula causa NullReferenceException.

this e ToString

  • this é a referência ao próprio objeto; útil quando o nome do parâmetro é igual ao do campo (this.nome = nome;).
  • ToString() vem de object (toda classe herda dela). Sobrescreva para definir como o objeto vira texto: public override string ToString() => $"{Nome} ({Idade})";
  • Inicializador de objeto: new Pessoa { Nome = "Ana", Idade = 20 }.

4. Modificadores de acesso

Regra: comece com o acesso mais restrito possível (private) e só abra o que for necessário.

5. Encapsulamento

Esconder os detalhes internos e expor só o necessário, de forma controlada. Assim, o objeto protege suas regras: ninguém de fora consegue deixá-lo em estado inválido.

Sem encapsulamentoCom encapsulamento
public decimal Saldo;
Qualquer um faz conta.Saldo = -999;		public decimal Saldo { get; private set; }
Só Depositar() e Sacar() alteram, aplicando as regras.
private decimal preco;                       // campo privado: guarda o dado
public decimal Preco                         // propriedade: a única porta de acesso
{
    get => preco;                            // leitura livre
    set
    {
        if (value <= 0)                      // "value" é o valor que tentaram atribuir
            throw new ArgumentException("O preço deve ser maior que zero.");
        preco = value;                       // só guarda se for válido
    }
}
💡 Princípio “diga, não pergunte” (tell, don't ask): em vez de buscar o saldo, comparar e alterar por fora, peça ao objeto que faça: conta.Sacar(100).

6. Sobrecarga e construtores

  • Sobrecarga: vários métodos (ou construtores) com o mesmo nome e parâmetros diferentes (quantidade ou tipos).
  • Construtor encadeado: public Livro(string t) : this(t, "Desconhecido") { } reaproveita outro construtor.
  • Se você não criar nenhum construtor, o C# cria um sem parâmetros. Se criar algum, aquele padrão deixa de existir.
  • Parâmetros opcionais e nomeados: new Produto("Arroz", 5m, quantidade: 10).

7. Herança

Uma classe filha (derivada) reaproveita tudo de uma classe base e acrescenta ou modifica o que for específico. Relação “é um”: um Carro é um Veiculo.

RecursoFunção
class Carro : VeiculoDeclara a herança
base(...)Chama o construtor da classe base
base.Metodo()Chama a versão da classe base dentro de uma sobrescrita
protectedMembro visível para as classes filhas
sealedImpede que uma classe seja herdada

O C# só permite uma classe base (herança simples), mas permite implementar várias interfaces. Toda classe herda, no fim, de object.

Herança ou composição?

PerguntaRelaçãoUse
X é um Y? (Carro é um Veículo)EspecializaçãoHerança
X tem um Y? (Pedido tem itens)Contém ou usaComposição

“Prefira composição à herança”: hierarquias profundas são frágeis (mudar a base quebra as filhas). Use herança só quando a relação “é um” for verdadeira e estável.

8. Polimorfismo

“Muitas formas”: o mesmo método chamado em objetos de classes diferentes executa comportamentos diferentes, escolhido em tempo de execução conforme o tipo real do objeto.

PalavraOndeSignificado
virtualMétodo da classe base“Pode ser sobrescrito”, com implementação padrão
overrideMétodo da classe filhaSobrescreve o método virtual ou abstract
abstractClasse ou método“Sem implementação; as filhas são obrigadas a criar”
List<Veiculo> frota = new() { new Carro(...), new Moto(...) };   // variável do tipo base, objetos de tipos diferentes
foreach (Veiculo v in frota)
{
    Console.WriteLine(v.CalcularDiaria());   // cada objeto executa a SUA versão de CalcularDiaria()
}

if (v is Carro carro)                         // pergunta o tipo real e já converte
{
    Console.WriteLine(carro.Portas);          // acessa algo exclusivo de Carro
}
  • Tipo da variável (estático) × tipo do objeto (dinâmico): a variável é Veiculo, mas o objeto pode ser Carro. O método virtual usa o tipo do objeto.
  • is testa o tipo; as converte e devolve null se não der; cast (Carro)v lança InvalidCastException se o tipo estiver errado.
  • Quando você precisar de muitos if (x is A) ... else if (x is B), provavelmente falta um método polimórfico na base.

9. Abstração: classes abstratas e interfaces

Abstrair é focar no essencial e ignorar os detalhes. Duas ferramentas:

CaracterísticaClasse abstrataInterface
Pode ter código pronto e campos?Sim (e membros abstratos)Define, em geral, só o contrato (o que deve existir)
Instanciar com newNãoNão
Quantas uma classe pode usar?Herda de umaImplementa várias
Relação“é um” (família)“sabe fazer” (capacidade)
ExemplosFuncionario, FormaIComparable<T>, INotificador, IDesconto
public interface INotificador                // contrato: quem implementar PRECISA ter este método
{
    void Enviar(string destinatario, string mensagem);
}

public class NotificadorEmail : INotificador // ": INotificador" = implementa a interface
{
    public void Enviar(string destinatario, string mensagem) { /* envia e-mail */ }
}

Programe para a interface, não para a implementação: uma classe que recebe um INotificador funciona com e-mail, SMS ou qualquer outro que apareça depois, sem alteração. Isso reduz o acoplamento e facilita testes. Por convenção, nomes de interface começam com I.

10. Composição, associação e coleções de objetos

Objetos podem conter ou usar outros: um Pedido tem uma lista de ItemPedido e um Cliente. Isso é composição/associação (“tem um”).

ConceitoIdeiaExemplo
AssociaçãoUm objeto conhece/usa outroPedido → Cliente
ComposiçãoA parte não existe sem o todoPedido ◆ ItemPedido
MultiplicidadeQuantos objetos se relacionam1 Pedido tem 0..* itens
  • Use List<T> para guardar vários objetos; exponha como IReadOnlyList<T> para que ninguém de fora altere a lista sem passar pelas regras da classe.
  • LINQ consulta coleções: Where (filtra), Select (transforma), OrderBy, Sum, Count, FirstOrDefault, Any.

12. Exceções e validação em classes

A classe deve proteger-se: validar no construtor e nas propriedades e lançar exceção quando algo violar uma regra.

ExceçãoQuando usar
ArgumentException / ArgumentNullExceptionArgumento inválido ou nulo
InvalidOperationExceptionA operação não é permitida no estado atual (ex.: sacar sem saldo)
public class SaldoInsuficienteException : Exception      // exceção PRÓPRIA do domínio
{
    public decimal SaldoAtual { get; }
    public SaldoInsuficienteException(decimal saldoAtual)
        : base($"Saldo insuficiente. Saldo atual: {saldoAtual:C2}")   // mensagem enviada à classe base
    {
        SaldoAtual = saldoAtual;
    }
}
// uso:  throw new SaldoInsuficienteException(Saldo);
// quem chama:  try { conta.Sacar(500); } catch (SaldoInsuficienteException ex) { Console.WriteLine(ex.Message); }

A classe lança a exceção; quem usa a classe (tela, menu) decide como mostrar a mensagem ao usuário.

13. Organização do código

  • Uma classe por arquivo, com o mesmo nome (Pessoa.cs).
  • Namespace: “pasta lógica” que agrupa classes e evita conflito de nomes (namespace Loja.Dominio;). Para usar de outro namespace: using Loja.Dominio;.
  • Para simplificar, os projetos deste módulo ficam no namespace global (sem declarar namespace).
  • Classes com nomes de substantivos (Pedido), métodos com nomes de verbos (AdicionarItem), propriedades em PascalCase.

PrincípioSignificado
Responsabilidade única (SRP)Cada classe tem um motivo para mudar: Pedido cuida do pedido, e não de enviar e-mail
Alta coesãoO que está dentro da classe tem a ver entre si
Baixo acoplamentoClasses dependem pouco umas das outras (preferir interfaces)
Aberto para extensão, fechado para modificaçãoNovo comportamento entra criando classes novas (polimorfismo), e não editando as antigas
DRYNão repetir regras: coloque na classe certa
Composição sobre herançaCombine objetos em vez de criar hierarquias profundas

16. Depuração de objetos

  • Coloque um ponto de interrupção (F9) e passe o mouse sobre uma variável: o DataTip mostra as propriedades do objeto.
  • As janelas Locais e Inspeção permitem expandir objetos e listas.
  • F11 entra no método (ou no construtor) chamado; a Pilha de Chamadas mostra o caminho.
  • Quando duas variáveis apontam para o mesmo objeto, mudar uma muda a outra: confira pelo Id do objeto (clique direito na variável → Criar ID de objeto).
