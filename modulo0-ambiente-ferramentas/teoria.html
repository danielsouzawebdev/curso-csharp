Teoria

🧭 Objetivo desta etapaCompreender como as ferramentas se relacionam e por que cada configuração existe antes de executar instalações e comandos.
Estratégia: leia uma seção por vez, execute mentalmente os exemplos e anote uma dúvida ou exemplo próprio antes de avançar para a prática.

1. O que é um ambiente de desenvolvimento

É o conjunto de ferramentas, configurações e versões que permite escrever, compilar, testar, executar e guardar o código. Um ambiente bem preparado evita o clássico “na minha máquina funciona” e permite que outra pessoa repita exatamente o que você fez (reprodutibilidade).

3. IDE: o que oferece

  • Editor inteligente (IntelliSense): sugere código e aponta erros enquanto você digita.
  • Designer de formulários (arrastar e soltar controles).
  • Depurador: pausa o programa e inspeciona variáveis.
  • Gerenciador de testes e NuGet integrados.
  • Git integrado (janelas Alterações do Git e Repositório).
  • Navegação e refatoração: ir para definição (F12), renomear (F2).

Edições do Visual Studio: a Community é gratuita para estudantes, desenvolvedores individuais e projetos de código aberto, com limites de uso em empresas (leia os termos de licença); Professional e Enterprise são pagas. Use sempre o site oficial e uma licença legítima: instaladores de fontes desconhecidas e “cracks” trazem malware e problemas legais.

5. Requisitos mínimos e recomendados

Todo software informa o que o computador precisa ter para funcionar. Mínimo significa “abre e roda”; recomendado significa “roda com conforto”. Valores do Visual Studio 2026 (confira a página oficial de requisitos do Visual Studio no Microsoft Learn):

Como interpretar

  • Cumpre o mínimo? Se alguma linha não cumpre, a instalação pode falhar ou ficar insuportavelmente lenta.
  • RAM: o Visual Studio, o navegador, o MySQL e o Windows disputam memória. Com 8 GB já é possível estudar; com 4 GB só com poucas coisas abertas.
  • Disco: considere também o espaço dos projetos, do Windows Update e de arquivos temporários.
  • Laboratório: multiplique por n máquinas e considere a rede: baixar 5 GB em 20 computadores ao mesmo tempo congestiona a internet. Há a opção de criar um layout offline do instalador.

6. Instalação e configuração

Etapas gerais de uma instalação profissional

  1. Verificar requisitos.
  2. Baixar do site oficial.
  3. Instalar com o perfil de uso correto (no Visual Studio: cargas de trabalho).
  4. Configurar (preferências, extensões, caminhos).
  5. Verificar se funciona (um teste simples).
  6. Documentar versões e parâmetros.

Cargas de trabalho do Visual Studio

Em vez de instalar tudo, você escolhe o que precisa. Para este curso: Desenvolvimento para desktop com .NET (inclui Windows Forms). Opcional: Desenvolvimento para ASP.NET e web para estender o estudo à web. Marque só o necessário: economiza disco e tempo.

Organização de pastas

  • Crie uma pasta curta, sem espaços e sem acentos: C:\Projetos.
  • Evite deixar os projetos dentro de pastas sincronizadas automaticamente (como OneDrive ou Google Drive): a sincronização pode travar arquivos de compilação (bin/obj) e gerar conflitos.
  • Uma pasta por projeto, e cada projeto é um repositório Git.

7. Controle de versão e repositórios

Controle de versão registra cada mudança do código, com autor, data e motivo, e permite voltar atrás, comparar e trabalhar em equipe sem sobrescrever o trabalho dos outros. O Git é o sistema mais usado; o GitHub é um serviço que hospeda repositórios Git na nuvem.

ConceitoSignificado
Repositório (repo)Pasta do projeto com todo o histórico
Repositório local / remotoO que está no seu computador / o que está no GitHub
Working directoryArquivos como estão agora na pasta
Staging (área de preparação)Mudanças escolhidas para o próximo commit (git add)
Commit“Foto” registrada do projeto, com uma mensagem
BranchLinha de desenvolvimento paralela
MergeJunção de uma branch em outra
CloneCopia um repositório remoto para o seu computador
Push / PullEnvia seus commits ao remoto / traz os commits do remoto
.gitignoreLista do que não deve ser versionado (bin/, obj/, senhas)
READMECartão de visita do projeto: o que é e como rodar

Ciclo básico

  1. Altere os arquivos.
  2. git status: veja o que mudou.
  3. git add: escolha o que entra no commit.
  4. git commit -m "mensagem": registre.
  5. git push: envie ao GitHub.
  6. git pull: traga as novidades antes de recomeçar.

Autenticação com o GitHub

O GitHub não aceita mais a senha da conta para operações Git pela linha de comando. No Windows, o Git Credential Manager (instalado com o Git para Windows) abre uma janela do navegador para você autorizar uma vez e guarda a credencial. Alternativas: token de acesso pessoal ou chave SSH. Nunca compartilhe seu token e nunca o coloque no código.

🔐 Git em computador compartilhado
  • Use git config --local user.name e git config --local user.email; evite --global.
  • Não marque opções para lembrar sessão, senha ou token.
  • Prefira autenticação temporária e com menor privilégio; ao terminar, confirme o push, faça logout e remova suas credenciais.
  • Token é senha: nunca coloque em código, README, print ou commit.

8. Boas práticas

  • Fonte oficial para todos os downloads, com licenças legítimas.
  • Verifique cada instalação com um teste simples (“Olá, mundo”, git --version).
  • Documente versões, caminhos e parâmetros em um README ou ficha do ambiente.
  • Mantenha atualizado, mas não troque a versão da ferramenta no meio de um projeto sem avisar a equipe.
  • Faça backup: o Git remoto é um backup do código; exporte também as configurações da IDE.
  • Segurança: não versionar senhas; manter o antivírus e o Windows atualizados.
