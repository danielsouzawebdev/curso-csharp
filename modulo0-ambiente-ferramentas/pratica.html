Prática guiada · Do zero ao ambiente verificado

🧭 Como executar esta práticaDigite o código, execute a cada etapa e compare o comportamento com o resultado descrito. Se houver erro, leia a mensagem antes de alterar o código e use o depurador quando indicado.

Faça as etapas na ordem e anote cada resultado na Ficha do Ambiente (modelo na Avaliação). Se algo falhar, não pule: consulte a seção de solução de problemas e registre o que aconteceu.

💡 Versões mudam. Os números e nomes de menus deste módulo foram conferidos na época da escrita (Visual Studio 2026 e .NET 10). Antes de instalar, confirme nas páginas oficiais da Microsoft, do Git, do GitHub e do Laragon; o professor deve validar o roteiro em uma máquina do laboratório.

Levante as características do seu computador

Abra o PowerShell (menu Iniciar → digite PowerShell) e rode os comandos abaixo, um por vez. Anote os resultados.

# Rode no PowerShell (menu Iniciar -> PowerShell). Linhas com # são comentários.

# 1) Versão do Windows e arquitetura (precisa ser 64 bits)
Get-CimInstance Win32_OperatingSystem | Select-Object Caption, Version, OSArchitecture

# 2) Processador: nome, núcleos físicos e núcleos lógicos
Get-CimInstance Win32_Processor | Select-Object Name, NumberOfCores, NumberOfLogicalProcessors

# 3) Memória RAM total em GB (dividimos os bytes por 1GB; Round arredonda para 1 casa)
[math]::Round((Get-CimInstance Win32_ComputerSystem).TotalPhysicalMemory / 1GB, 1)

# 4) Espaço livre no disco C: em GB
[math]::Round((Get-PSDrive C).Free / 1GB, 1)

# 5) Tipo de cada disco (SSD ou HDD) e tamanho
Get-PhysicalDisk | Select-Object FriendlyName, MediaType, Size

Planeje o ambiente

Liste o que será instalado e em qual ordem. Sugestão: 1) Visual Studio (com o SDK do .NET) → 2) Git → 3) conta no GitHub → 4) Laragon → 5) verificação. Crie a pasta de projetos no PowerShell:

mkdir C:\Projetos

Escolha onde instalar (prefira o SSD) e defina quem é o responsável por documentar cada etapa, se estiver em grupo.

Instale o Visual Studio

  1. Baixe o Visual Studio Community no site oficial da Microsoft (visualstudio.microsoft.com).
  2. Execute o instalador (será pedida permissão de administrador). Ele instala primeiro o Visual Studio Installer.
  3. Na tela de cargas de trabalho, marque Desenvolvimento para desktop com .NET. Observe, no painel à direita, o espaço total necessário.
  4. Na aba Componentes individuais, confirme que Git para Windows está marcado (se aparecer na lista). Na aba Pacotes de idiomas, escolha Português (Brasil) ou Inglês.
  5. Na aba Locais de instalação, confira a unidade (prefira o SSD).
  6. Clique em Instalar e aguarde (pode demorar; o tempo depende da internet e do disco). Reinicie se solicitado.
  7. Ao abrir pela primeira vez, entre com sua conta Microsoft (ou pule) e escolha o tema de cores.

Verifique o SDK do .NET

O Visual Studio instala o SDK junto com a carga de trabalho. Confira pelo terminal:

# Abra o PowerShell (ou o terminal do Visual Studio: Exibir > Terminal)

dotnet --version        # mostra a versão do SDK que está em uso
dotnet --list-sdks      # lista todos os SDKs instalados (podem existir vários)
dotnet --list-runtimes  # lista os runtimes instalados
dotnet --info           # relatório completo: SDK, runtimes, sistema operacional

Crie e execute o primeiro projeto de console

Pelo terminal (e depois repita pela IDE: Arquivo → Novo → Projeto → Aplicativo de Console):

cd C:\Projetos                      # entra na pasta de projetos (crie com: mkdir C:\Projetos)
dotnet new console -n OlaConsole    # cria um projeto de console chamado OlaConsole
cd OlaConsole                       # entra na pasta do projeto criado
dotnet run                          # compila e executa; deve aparecer "Hello, World!"
dotnet build                        # só compila (útil para ver erros sem executar)

Crie o primeiro projeto Windows Forms

  1. Visual Studio → Criar um projeto → Aplicativo do Windows Forms (C#) → Avançar.
  2. Nome OlaMundo, local C:\Projetos → Avançar → escolha o .NET LTS oferecido → Criar.
  3. No formulário, adicione (Caixa de Ferramentas): um TextBox (Name = txtNome), um Button (Name = btnOla, Text = “Cumprimentar”) e um Label (Name = lblSaudacao, Text vazio).
  4. Dê clique duplo no botão para criar o evento e escreva:
// Evento de clique do botão btnOla (clique duplo no botão, no designer, cria este método).
private void btnOla_Click(object sender, EventArgs e)
{
    string nome = txtNome.Text.Trim();          // lê o texto digitado; Trim remove espaços das pontas

    if (nome == "")                             // se o campo estiver vazio...
    {
        MessageBox.Show(                        // ...mostra uma janelinha de aviso
            "Digite seu nome primeiro.",        // mensagem
            "Atenção",                          // título da janela
            MessageBoxButtons.OK,               // só o botão OK
            MessageBoxIcon.Information);        // ícone de informação
        return;                                 // sai do método, sem fazer mais nada
    }

    lblSaudacao.Text = $"Olá, {nome}! Seu ambiente está funcionando.";  // $"..." insere a variável no texto
}

Execute e confira

Pressione F5. Digite seu nome e clique no botão. Teste também com o campo vazio. Se aparecer a saudação, o Visual Studio, o SDK e o Windows Forms estão funcionando. Feche a janela, e depois use Ctrl+F5 para executar sem depurar.

Instale e configure o Git

  1. Se o Git ainda não estiver instalado, baixe o Git para Windows no site oficial (git-scm.com) e instale aceitando as opções padrão (inclui o Git Credential Manager).
  2. Feche e reabra o PowerShell, e rode:
git --version                                   # confirma que o Git está instalado (mostra a versão)

# Em computador de laboratório, NÃO grave sua identidade com --global.
# A identidade será configurada com --local dentro de cada repositório.
# Isso evita deixar seus dados configurados para o próximo usuário.
⚠ Computador compartilhadoNunca salve senha ou token no navegador/sistema. Se a máquina solicitar permanência da autenticação, recuse. Ao terminar, confirme o push, faça logout do GitHub e remova suas credenciais. Se utilizar um Personal Access Token, prefira um token com menor privilégio, expiração curta e revogue-o após a atividade.

Crie a conta e o repositório no GitHub

  1. Acesse github.com e crie sua conta (use e-mail válido e senha forte; ative a verificação em duas etapas).
  2. Clique em New repository. Nome: ola-mundo. Marque Public ou Private (conforme orientação do professor). Não marque “Add a README” agora (vamos criar na prática). Clique em Create repository.
  3. Copie o endereço HTTPS do repositório (algo como https://github.com/seu-usuario/ola-mundo.git).

Seu primeiro ciclo de Git

Rode no PowerShell, dentro da pasta do projeto. Na primeira vez que fizer o push, o Git Credential Manager abrirá o navegador para você entrar no GitHub e autorizar. Antes de começar, crie um README.md com uma linha (por exemplo, # OlaMundo) e adicione um .gitignore adequado ao Visual Studio (pelo menu Git → Criar Repositório Git no Visual Studio, que gera o arquivo, ou copie o modelo “VisualStudio” do repositório github/gitignore). Esse arquivo evita enviar as pastas bin/ e obj/.

cd C:\Projetos\OlaMundo                          # entra na pasta do projeto Windows Forms

git init -b main                                 # cria o repositório já usando a branch main

git config --local user.name "Seu Nome Completo"       # identidade SOMENTE deste repositório
git config --local user.email "seu-email@exemplo.com"  # use o e-mail associado à sua conta GitHub
git config --local --list                        # confira antes de continuar

git status                                       # mostra o que mudou; arquivos novos aparecem em vermelho

git add .                                        # "." = tudo; coloca os arquivos na área de preparação
git status                                       # agora aparecem em verde, prontos para o commit
git commit -m "chore: projeto inicial OlaMundo"  # registra o primeiro commit com uma mensagem clara

git branch -M main                               # garante que a branch se chama "main"
git remote add origin https://github.com/SEU-USUARIO/ola-mundo.git   # liga ao repositório do GitHub (nome "origin")
git push -u origin main                          # envia os commits; -u lembra o destino para os próximos push

Pratique commit, histórico, branch e pull

Repita o ciclo várias vezes até ficar natural. Depois, faça o mesmo pelo Visual Studio: janela Alterações do Git (menu Git → Alterações do Git): escreva a mensagem, clique em Confirmar Tudo e depois em Enviar; veja o histórico em Git → Exibir Histórico de Branch. Compare: é o mesmo que os comandos.

# --- 1) Fazer uma mudança e registrá-la ---
# (altere o texto de um Label no designer ou edite o README.md)
git status                                       # confirma quais arquivos mudaram
git diff                                         # mostra linha a linha o que mudou (aperte q para sair)
git add .
git commit -m "feat: mensagem de boas-vindas na tela"
git push                                         # envia ao GitHub

# --- 2) Ver o histórico ---
git log --oneline                                # um commit por linha, mais recente primeiro

# --- 3) Trabalhar em uma branch ---
git switch -c feature/botao-limpar               # cria a branch e já entra nela
# ... faça mudanças e commits ...
git switch main                                  # volta para a main
git merge feature/botao-limpar                   # junta a branch na main
git push

# --- 4) Trazer mudanças feitas no GitHub (simulando um colega) ---
# No site do GitHub, edite o README.md e salve (commit).
git pull                                         # baixa e junta o commit do GitHub no seu computador

Instale o Laragon e inicie o MySQL

  1. Baixe o Laragon Full no site oficial (laragon.org) e execute o instalador com as opções padrão.
  2. Abra o Laragon e clique em Iniciar tudo (Start All). Aparecem os números das portas do Apache e do MySQL.
  3. Janelas de licença: versões recentes podem exibir avisos pedindo chave de licença. Leia os termos no site oficial; o professor deve confirmar se o uso na escola está de acordo com eles. Para os exercícios deste curso, qualquer servidor MySQL ou MariaDB local funciona.
  4. Clique em Banco de dados para abrir o HeidiSQL e conecte à sessão (servidor 127.0.0.1, usuário root, senha vazia, porta 3306; confira os valores na sua instalação). Execute SELECT VERSION();.

Se o MySQL não iniciar, provavelmente a porta 3306 está ocupada por outro programa (outro MySQL, XAMPP...). Descubra quem usa:

# Descobrir quem está usando a porta 3306 (rode no PowerShell ou Prompt de Comando)
netstat -ano | findstr :3306                     # lista conexões na porta; o último número é o PID do processo

# Descobrir o nome do programa a partir do PID (troque 1234 pelo número encontrado)
tasklist /FI "PID eq 1234"                       # mostra o nome do processo, por exemplo mysqld.exe

Escreva o programa de verificação do ambiente

Crie um novo projeto de Aplicativo de Console chamado VerificaAmbiente em C:\Projetos. Instale o driver do MySQL e substitua o conteúdo de Program.cs pelo código que vem depois dos comandos. Rode com F5 ou pelo terminal.

cd C:\Projetos\VerificaAmbiente                 # entra na pasta do projeto de console
dotnet add package MySqlConnector                # instala o driver do MySQL via NuGet no projeto
dotnet run                                       # executa o programa de verificação
using System.Runtime.InteropServices;                                  // dá acesso a RuntimeInformation (informações da máquina)
using MySqlConnector;                                                  // driver do MySQL (instale: dotnet add package MySqlConnector)

Console.WriteLine("=== Verificação do ambiente ===");                  // título do relatório

Console.WriteLine($".NET em execução: {RuntimeInformation.FrameworkDescription}"); // versão do .NET que roda este programa
Console.WriteLine($"Sistema operacional: {RuntimeInformation.OSDescription}");    // nome e versão do Windows
Console.WriteLine($"Arquitetura do processo: {RuntimeInformation.ProcessArchitecture}"); // X64, Arm64...
Console.WriteLine($"Núcleos lógicos: {Environment.ProcessorCount}");  // quantos "processadores" o Windows enxerga
Console.WriteLine($"Computador: {Environment.MachineName}");          // nome da máquina

const string conexao = "Server=localhost;Port=3306;User ID=root;Password=;"; // sem Database: só testa o servidor

try                                                                    // tenta conectar ao MySQL
{
    using var con = new MySqlConnection(conexao);                      // using var: fecha a conexão sozinho no fim
    con.Open();                                                        // abre a conexão de fato
    Console.WriteLine($"MySQL: conectado (versão {con.ServerVersion})"); // mostra a versão do servidor
}
catch (MySqlException ex)                                              // se a conexão falhar...
{
    Console.WriteLine("MySQL: FALHA na conexão -> " + ex.Message);     // ...mostra o motivo técnico
    Console.WriteLine("Dica: o MySQL está iniciado no Laragon?");      // ...e uma pista do que verificar
}

Console.WriteLine("Pressione qualquer tecla para sair...");            // evita fechar a janela de uma vez
Console.ReadKey();                                                     // espera uma tecla

Interprete o resultado

Se tudo estiver certo, você verá a versão do .NET, o Windows, a arquitetura X64 (ou Arm64) e “MySQL: conectado”. Anote as versões na Ficha do Ambiente. Se aparecer FALHA, confira se o MySQL está iniciado no Laragon e se a porta e a senha estão corretas.

Documente e versione

  1. Crie o repositório meu-ambiente no GitHub e coloque nele o projeto VerificaAmbiente e um README.md com a Ficha do Ambiente preenchida (versões e parâmetros).
  2. Faça commits com mensagens claras (docs: ficha do ambiente, feat: programa de verificação).
  3. Peça a um colega para clonar o repositório (git clone endereço) e executar o programa na máquina dele. Funcionou? O que faltou no README?

Manutenção do ambiente

Faça, e registre, a rotina de manutenção:

  • Atualizar o Visual Studio: abra o Visual Studio Installer → botão Atualizar.
  • Atualizar o Git: baixe o instalador novo; o comando git update-git-for-windows também funciona nas versões recentes.
  • Backup das configurações: exporte as configurações da IDE.
  • Limpeza: apague as pastas bin e obj de projetos antigos (o Visual Studio recria ao compilar).
  • Reparar: no Installer, o botão Mais → Reparar corrige instalações com problemas.
