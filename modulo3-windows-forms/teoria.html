1. O que é o Windows Forms

Windows Forms (WinForms) é a biblioteca do .NET para criar aplicativos de desktop para Windows com interface gráfica. Você monta a tela arrastando controles no designer e programa o que acontece quando o usuário interage. Cada janela é um objeto da classe Form, e cada botão, caixa de texto etc. também é um objeto: tudo o que você aprendeu de POO se aplica.

CaracterísticaObservação
PlataformaSomente Windows (no .NET moderno, a partir do .NET Core 3.0)
Modelo de programaçãoOrientado a eventos
Ferramenta principalDesigner do Visual Studio
Ótimo paraSistemas de gestão, cadastros, ferramentas internas

2. Programação orientada a eventos

Em um programa de console, você controla a ordem (pergunta, lê, calcula). Em uma janela, é o usuário quem decide o que fazer: clicar, digitar, fechar. O programa fica esperando e reage a cada ação. Cada ação gera um evento; o método que responde a ele é o manipulador de evento (event handler).

  • Application.Run(form) inicia o loop de mensagens: o programa fica em repouso até chegar uma mensagem do Windows.
  • Toda a interface roda em uma única thread (a thread da interface). Se um método demorar, a janela congela (veja a seção 11).

3. Anatomia de um projeto Windows Forms

ArquivoFunçãoEdita?
Program.csPonto de entrada: cria e executa o primeiro formulárioRaramente
Form1.cs (código)Seu código: eventos e lógica (code-behind)Sim (tecla F7)
Form1.Designer.csCódigo gerado pelo designer: cria e configura cada controleNão
Form1.resxRecursos (imagens, textos) do formulárioPelo designer
// Program.cs
static class Program
{
    [STAThread]                                   // exigido pelo Windows Forms (modelo de threads da interface)
    static void Main()
    {
        ApplicationConfiguration.Initialize();    // configura estilos visuais, fonte padrão e DPI
        Application.Run(new Form1());             // cria o formulário e inicia o loop de mensagens
    }
}

// Form1.cs (parte SUA)                           // "partial": a classe é dividida em dois arquivos
public partial class Form1 : Form
{
    public Form1()
    {
        InitializeComponent();                    // método GERADO no Designer.cs: cria e posiciona os controles
    }
}

Quando você arrasta um botão, o designer escreve em Form1.Designer.cs algo como this.btnSalvar = new Button(); this.btnSalvar.Text = "Salvar"; this.btnSalvar.Click += new EventHandler(this.btnSalvar_Click);. Você nunca precisa escrever isso à mão, mas precisa entender: controles são objetos criados em código.

💡 Alterne entre o designer e o código com F7 (código) e Shift+F7 (designer). Se o designer mostrar erro, compile (Ctrl+Shift+B) e corrija o erro de compilação antes.

6. Eventos na prática

Um manipulador tem sempre dois parâmetros:

private void btnSalvar_Click(object sender, EventArgs e)
{
    // sender = o objeto que gerou o evento (o botão que foi clicado)
    // e      = dados do evento (EventArgs vazio no Click; outros eventos trazem informações)
}
EventoControleParâmetro e útil
Click · DoubleClickQuase todos—
TextChangedTextBox—
KeyPressTextBoxKeyPressEventArgs: e.KeyChar, e.Handled
KeyDownQualquer controleKeyEventArgs: e.KeyCode, e.Control
SelectedIndexChangedComboBox, ListBox, TabControl—
CheckedChangedCheckBox, RadioButton—
CellClick · CellFormattingDataGridViewe.RowIndex, e.ColumnIndex
ValidatingControles de entradaCancelEventArgs: e.Cancel
FormClosingFormFormClosingEventArgs: e.Cancel, e.CloseReason
PaintControles e formuláriosPaintEventArgs: e.Graphics

Como ligar um evento

  1. Designer: clique duplo no controle (evento padrão) ou selecione o controle, clique no ícone de raio ⚡ na janela Propriedades e dê clique duplo no evento.
  2. Código: btn.Click += MeuManipulador; (útil para controles criados em código e para vários controles com o mesmo manipulador).

Para usar o mesmo manipulador em vários controles, use o sender: if (sender is Button b) { MessageBox.Show(b.Text); }. Para impedir uma tecla no KeyPress, faça e.Handled = true;.

⚠️ Cuidado: se você apagar um controle, o método do evento continua no código (apague também). Se renomear um controle depois de criar o evento, o método mantém o nome antigo: o ideal é renomear o controle antes, ou usar Renomear (F2) no código.

9. Dados nos controles

  • Itens simples: listBox.Items.Add(objeto): o controle mostra o ToString() do objeto; SelectedItem devolve o objeto de volta.
  • DataSource: liga o controle a uma lista. No ComboBox/ListBox, defina DisplayMember (o que mostrar) e ValueMember (o valor) antes do DataSource.
  • BindingList<T> (using System.ComponentModel;): quando você adiciona ou remove itens da lista, a grade atualiza sozinha. Se você alterar uma propriedade de um item, chame dgv.Refresh() (ou implemente INotifyPropertyChanged).
  • DataGridView: colunas automáticas a partir das propriedades públicas; ajuste com Columns["Nome"].HeaderText, DefaultCellStyle.Format = "C2", Visible = false. Pegue o objeto da linha com CurrentRow?.DataBoundItem.
  • ListView (modo Details): crie ListViewItem e guarde o objeto em Tag.

10. Arquitetura: a interface não é o sistema

Colocar regras de negócio dentro do método do botão cria código difícil de testar e de reaproveitar. O caminho correto:

CamadaResponsabilidade
Formulário (UI)Ler os campos, chamar as classes, mostrar o resultado e as mensagens
Classes de domínioRegras e validações (as que você criou no Módulo 2)
Acesso a dadosBanco ou arquivo (Módulo 5)

Sinal de alerta: um método de evento com dezenas de linhas, cálculos e if de regras. Extraia para uma classe ou método próprio.

11. Interface responsiva: threads, async e await

A interface roda em uma única thread. Se um evento executa algo demorado (Thread.Sleep, cálculo pesado, rede, banco), a janela congela até terminar: sem repintar, sem responder a cliques.

SituaçãoSolução
Esperar um tempoawait Task.Delay(1000) em um método async
Cálculo pesadoawait Task.Run(() => Calcular())
Rede, arquivos, bancoMétodos assíncronos (ReadAllTextAsync, HttpClient...)
Atualizar um controle a partir de outra threadProibido (InvalidOperationException: acesso entre threads). Depois do await você já volta à thread da interface; senão use Invoke

Manipuladores de evento async são os únicos casos em que se usa async void. Desabilite o botão durante a operação para evitar cliques repetidos.

12. Depuração em Windows Forms

  • Coloque o ponto de interrupção (F9) dentro do manipulador; ao clicar no botão, a execução para ali.
  • Evento “não dispara”? Confira se ele está ligado (ícone ⚡ nas Propriedades) e se não há duplicidade (duas assinaturas executam duas vezes).
  • NullReferenceException no Load: dados ainda não carregados ou controle sem inicializar.
  • Tratamento global: Application.ThreadException captura exceções não tratadas da interface e evita que o programa feche sem aviso.
  • Registro (log): grave erros em arquivo para investigar depois.
