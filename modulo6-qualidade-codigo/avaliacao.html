Avaliação e verificação

🧠 Como usar esta avaliaçãoFaça primeiro sem consultar a teoria. Marque as questões em que teve dúvida, volte ao conteúdo apenas depois da primeira tentativa e corrija suas respostas explicando por que a solução correta funciona. A rubrica serve para autoavaliação e para feedback do professor.
✅ Evidência de aprendizagemResolva sem copiar a resposta dos exemplos. Quando houver código, execute e teste. O objetivo é demonstrar que você consegue explicar, aplicar e diagnosticar os conceitos deste módulo.

1. Checklist de revisão de código

Use para revisar o seu código e o de um colega. ✔ atende · ✖ não atende.

#CritérioSituação
1O código cumpre cada requisito listado?
2Nomes de classes, métodos e variáveis seguem o padrão e são claros?
3Não há números ou textos “mágicos” repetidos?
4Cada método faz uma única coisa e é curto?
5Não existe código repetido (DRY)?
6Membros públicos têm comentário ///?
7Comentários explicam o porquê e não o óbvio? Não há código comentado?
8Entradas inválidas são tratadas com exceções adequadas?
9Há testes para cada requisito, incluindo casos limite?
10Todos os testes passam?
11Commits pequenos e com mensagem que cita o requisito?

2. Exercícios

  1. TDD (Red-Green-Refactor). Novo requisito: “RF07: a conta poupança rende juros: AplicarRendimento(decimal taxa) soma ao saldo o valor de saldo × taxa, desde que o saldo seja positivo e a taxa maior que zero. Em conta corrente, o método lança InvalidOperationException.” Escreva primeiro os testes (devem falhar), depois o código mínimo para passar e, por fim, refatore.
  2. Identifique o erro pelo requisito. Para cada trecho, diga qual requisito viola e como corrigir:
    TrechoRequisito
    if (valor > Saldo) throw ...; no Sacar de uma conta correnteRF03/RF04
    Limite => 500; para qualquer tipo de contaRF04
    movimentacoes.Insert(0, mov); em RegistrarRF06
    Titular = titular; sem Trim() (aceita “ A ”)RF01
  3. Documente. Adicione comentários XML completos a uma classe sua (summary, param, returns e exception) e confira o texto que aparece no IntelliSense ao usar o método.
  4. Refatore. O código abaixo repete uma regra. Aplique Extrair Método e rode os testes:
    public void Debitar(decimal valor)
{
    if (valor <= 0) throw new ArgumentException("Valor inválido.");
    Saldo -= valor;
}
public void Creditar(decimal valor)
{
    if (valor <= 0) throw new ArgumentException("Valor inválido.");
    Saldo += valor;
}
  5. Depure e registre. Introduza um defeito novo de propósito na classe (por exemplo, troque -= por += no saque), troque o código com um colega, e peça para ele encontrar o defeito usando só testes e depurador, preenchendo o diário de depuração.
  6. Meça. Crie um teste de desempenho no console comparando List.Contains e HashSet.Contains com 100.000 itens e escreva uma conclusão.

5. Solução de problemas

SintomaCausa provávelO que fazer
Gerenciador de Testes vazioProjeto não compilouCompilar a solução (Ctrl+Shift+B) e abrir o gerenciador de novo
Erro CS0246 ou CS0122 nos testes (“tipo não encontrado” ou “inacessível”)Falta referência ao projeto, using, ou a classe não é publicAdicionar a referência de projeto, using Banco.Core; e conferir public class
Ponto de interrupção “oco” (não para)Compilação em Release ou código desatualizadoUsar a configuração Debug e recompilar
Teste passa sozinho mas falha junto com outrosTestes dependem de estado compartilhadoCriar os objetos dentro de cada teste (isolamento)
Tempos do Stopwatch muito diferentes a cada rodadaMedição em Debug ou com outros programas abertosUsar Release (Ctrl+F5), repetir e comparar a média
Warning de documentação XML (CS1591)Membro público sem ///Documentar ou desativar o aviso apenas se justificado

7. Glossário

TermoSignificado
RefatoraçãoMelhorar a estrutura do código sem alterar o comportamento
DRYDon't Repeat Yourself: cada regra em um só lugar
Teste unitárioTeste automático de uma pequena unidade de código
AAAArrange, Act, Assert: estrutura de um teste
TDDDesenvolvimento guiado por testes (Red, Green, Refactor)
RegressãoDefeito que reaparece depois de uma mudança; os testes o detectam
Ponto de interrupçãoMarca que pausa a execução em uma linha
RastreabilidadeLigação entre requisito, código, teste e commit
CommitRegistro de um conjunto de mudanças no histórico do Git
Code smellSinal de que o código pode ter um problema de estrutura
